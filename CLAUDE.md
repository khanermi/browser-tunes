# browser-tunes

Публичный репозиторий с личными userscript'ами для Tampermonkey. Каждый файл —
самостоятельный скрипт, без сборки и без общих зависимостей между скриптами.

## Как это работает

- Скрипты лежат плоско в корне репозитория: `<name>.user.js`.
- Каждый скрипт содержит `@updateURL` и `@downloadURL`, указывающие на
  `https://raw.githubusercontent.com/khanermi/browser-tunes/main/<файл>`.
  Tampermonkey сам подтягивает обновления с этого URL — отдельного релиза
  или CI не требуется.
- Рабочий процесс обновления: правим файл → бампим `@version` в шапке →
  коммитим → пушим в `main`. Без бампа версии Tampermonkey не увидит апдейт.
- `@namespace` у всех скриптов — `local` (это просто метка Tampermonkey,
  на логику не влияет).
- Внешние библиотеки подключаются через `@require` на CDN с закреплённой
  версией (не через bundler) — см. пример в
  `aliexpress-invoice-generator.user.js`.

## Что уже лежит в репозитории

### `fake-fullscreen-episode-nav.user.js`
Сайт: `rezka.ag`. Два независимых улучшения плеера:
- Псевдо-fullscreen (не нативный Fullscreen API, а `position: fixed` на
  контейнер плеера на весь viewport) — вызывается через F9 или через перехват
  кнопки Picture-in-Picture (нативный PiP тут же закрывается, вместо него
  включается псевдо-fullscreen). Родной hotkey `F` плеера не трогаем.
- `Ctrl+←/→` — переключение на предыдущую/следующую серию текущего сезона
  через доступный на странице список серий, с переносом фокуса на `<video>`.

Устройство сайта, за которое отвечает список серий, вынесено в массив
`profiles` (`match/getItems/isActive/select`) — так можно добавить поддержку
другого сайта, не трогая логику fullscreen/hotkeys. Раньше был профиль под
`yummyani.me`, его убрали (см. историю коммитов) — общий код это позволяет
сделать без переписывания остального скрипта.

### `aliexpress-invoice-generator.user.js`
Сайт: `aliexpress.com/p/order/detail*`. Портированная логика Chrome-расширения
[`InvoiceExtension`](https://github.com/khanermi/InvoiceExtension) (парсинг
заказа + генерация PDF-фактуры по польским требованиям), переписанная в один
userscript, чтобы не поддерживать отдельное расширение:

- Парсит страницу заказа (товары, цену, дату, продавца, НДС), добавляет
  кнопку "Faktura (PDF)".
- Вместо отдельной страницы расширения (`chrome.tabs.create`) редактор
  инвойса открывается модалкой поверх текущей страницы (все id/классы с
  префиксом `ig-`, чтобы не конфликтовать с версткой AliExpress).
- Реквизиты покупателя (своей фирмы) хранятся через `GM_setValue`/
  `GM_getValue`, редактируются через пункт меню Tampermonkey
  ("⚙️ Ustawienia nabywcy").
- PDF собирается через `pdfmake` — подключён через `@require` с cdnjs,
  версия закреплена (`0.3.3`); `vfs_fonts.js` от той же версии подключён
  отдельным `@require` следом (порядок важен — `vfs_fonts.js` регистрирует
  шрифты в уже загруженном `pdfMake`).
- Оригинальные CSS-селекторы парсинга DOM AliExpress скопированы как есть из
  расширения — при изменении вёрстки AliExpress могут потребовать правки
  (это уязвимое место любого DOM-скрапинга, не специфика userscript'а).

## Общие детали по будущим задачам

- Новый скрипт — новый файл в корне, с обязательными
  `@updateURL`/`@downloadURL` по образцу существующих (иначе автообновление
  не заработает).
- Если скрипту нужна внешняя библиотека — тянуть через `@require` с
  зафиксированной версией на CDN (cdnjs/jsdelivr), не копировать код
  библиотеки в репозиторий.
- Изменения в существующем скрипте всегда сопровождаются бампом `@version`
  в этом же коммите.
- Никакого README/CI/package.json не заводим — репозиторий сознательно
  остаётся плоским набором `.user.js`.
