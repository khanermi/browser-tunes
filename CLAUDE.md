# browser-tunes

Публичный репозиторий с личными userscript'ами для Tampermonkey. Каждый файл —
самостоятельный скрипт, без сборки и без общих зависимостей между скриптами.

## Как это работает

- Скрипты лежат плоско в корне репозитория: `<name>.user.js`.
- Каждый скрипт содержит `@updateURL` и `@downloadURL`, указывающие на
  `https://raw.githubusercontent.com/khanermi/browser-tunes/main/<файл>`.
  Tampermonkey сам подтягивает обновления с этого URL — отдельного релиза
  или CI не требуется.
- Рабочий процесс обновления: правим файл → бампим `@version` в шапке →
  коммитим → пушим в `main`. Без бампа версии Tampermonkey не увидит апдейт.
- `@namespace` у всех скриптов — `local` (это просто метка Tampermonkey,
  на логику не влияет).
- Внешние библиотеки подключаются через `@require` на CDN с закреплённой
  версией (не через bundler) — см. пример в
  `aliexpress-zestawienie-generator.user.js`.

## Что уже лежит в репозитории

### `fake-fullscreen-episode-nav.user.js`
Сайт: `rezka.ag`. Два независимых улучшения плеера:
- Псевдо-fullscreen (не нативный Fullscreen API, а `position: fixed` на
  контейнер плеера на весь viewport) — вызывается через F9 или через перехват
  кнопки Picture-in-Picture (нативный PiP тут же закрывается, вместо него
  включается псевдо-fullscreen). Родной hotkey `F` плеера не трогаем.
- `Ctrl+←/→` — переключение на предыдущую/следующую серию текущего сезона
  через доступный на странице список серий, с переносом фокуса на `<video>`.

**Серии бывают `<li>` и `<a href>`** (6.3). На обычных страницах сериала
`.b-simple_episode__item` — `<li>`, и сайт переключает серию аяксом
(делегированный `click.player_episode` на `#player`). Но на страницах с URL
вида `.../238-subtitles/1-season/3-episode.html` (SEO-ссылки на серию) это
`<a href>`, и обработчик сайта их явно пропускает (`tagName != 'a'`) — клик
по ним = полная перезагрузка страницы: вылет из fullscreen (и родного, и
псевдо) и потеря фокуса. Поэтому для `<a>` скрипт вставляет рядом скрытый
временный `<li data-ffen-proxy>` с теми же `data-*` и кликает его: сайт
грузит серию аяксом и ставит `active` на прокси; скрипт ловит это, переносит
`active` на настоящую `<a>`, удаляет прокси и через `history.replaceState`
ставит адрес выбранной серии (перезагрузка откроет её же). Пока идёт загрузка
(у нас pending или у сайта `.disabled` на списке), повторные `Ctrl+←/→`
игнорируются. Если обработчика сайта на `#player` нет — старый `el.click()`.

Устройство сайта, за которое отвечает список серий, вынесено в массив
`profiles` (`match/getItems/isActive/select`) — так можно добавить поддержку
другого сайта, не трогая логику fullscreen/hotkeys. Раньше был профиль под
`yummyani.me`, его убрали (см. историю коммитов) — общий код это позволяет
сделать без переписывания остального скрипта. Поддержка yummyani вернулась
не сюда, а отдельным скриптом `yummyani-episode-nav.user.js` (см. ниже):
у сайтов слишком разная механика (псевдо-fullscreen там свой, с 1.3).

### `yummyani-episode-nav.user.js`
Сайт: `old.yummyani.me`. `Ctrl+←/→` — переключение серии текущей
озвучки/плеера, с переносом фокуса на `<video>` внутри плеера (чтобы Space
после переключения сразу работал как play/pause). С 1.3 `F9` — псевдо-fullscreen
любого плеера (`Esc` — выход), а кнопка PiP плеера Alloha включает его же.

Что важно знать про DOM этого сайта (всё проверено дебагом на живой странице,
а не унаследовано из старой реализации):

- **Список серий ищется структурно, а не по классам.** Классы —
  перегенерируемые хэши (`Y56k`, `Yqy0`, `WYvA`, `gRQ9`), их нельзя
  захардкодить. Берём внутри стабильного `#video` видимый контейнер, у
  которого большинство детей — чистый номер серии; такой на странице ровно
  один.
- **Тумблер "Новый дизайн" трогать не нужно.** Он живёт в
  `localStorage.designSwitch` (`"true"` = новый дизайн включён) и меняет
  вёрстку: при `true` появляется `#video .selectors` с react-select
  дропдаунами, при `false` — развёрнутый список строк озвучек
  (`.WYvA > .gRQ9`), внутри выбранной из которых лежит список серий.
  Структурный поиск выше работает в обоих вариантах одинаково, поэтому
  скрипт не переключает настройку сайта за пользователя.
- **Списки серий невыбранных озвучек в DOM не висят** — рендерятся лениво
  только для текущего выбора, так что промахнуться мимо активного списка
  нельзя.
- **Активная серия определяется по цветному фону**, а не по классу: у пункта
  три состояния (не просмотрено `rgb(34,34,34)` / просмотрено `rgb(75,75,75)`
  / активно `rgb(60,206,123)`), и только активное — не серое (`max(r,g,b) -
  min(r,g,b) > 15`). Класс-маркер активной серии тоже существует, но он
  один-в-один совпадает по вычисленным стилям с обычным пунктом, а у
  "просмотрено" свой отдельный класс — по классам состояния надёжно не
  различить.
- **Зелёный фон догоняет клик с задержкой ~1-1.5 с** (он привязан к тому,
  что плеер реально загрузил серию). Поэтому скрипт держит «оптимистичный»
  указатель на только что выбранную серию (`PENDING_MS`): без него быстрые
  повторные `Ctrl+→` читают устаревшее состояние и топчутся на месте.
- **Плеер — cross-origin iframe**, поэтому в `@match` кроме `old.yummyani.me`
  стоят домены плееров (`kodikplayer.com`, `video.sibnet.ru`,
  `alloha.yani.tv`, а также `ru.yummyani.me`, с которого отдаётся плеер CVH).
  Внутри iframe скрипт пробрасывает хоткей наверх через `postMessage`.
  Это не опционально: после переключения фокус уходит в плеер, так что уже
  второе нажатие подряд ловится именно там. Чтобы не мешать этим доменам на
  чужих сайтах, перехват хоткея внутри iframe включается только если
  `document.referrer` — домен yummyani; иначе скрипт ничего не перехватывает.
- **Фокус после переключения ставится на `<video>` внутри плеера, а не на сам
  `<iframe>`.** Фокус на `<iframe>` как на элементе страницы обязателен (иначе
  `keydown` вообще не долетает до плеера), но его мало: Space (play/pause)
  тогда срабатывает через раз — куда он уйдёт, решает JS самого плеера.
  Дотянуться до `<video>` из топ-документа нельзя (cross-origin), поэтому топ
  шлёт вниз `postMessage` "забери фокус на видео", а фокус ставит ветка
  скрипта, исполняющаяся внутри плеера, и отвечает подтверждением. Просьба
  шлётся серией (~каждые 400 мс, окно 6 с) до подтверждения: сайт после клика
  по серии пересоздаёт `<iframe>`, и первое сообщение почти всегда уходит в
  ещё не загруженный документ. Внутри плеера `<video>` тоже ждут опросом
  (серия грузится асинхронно) и при необходимости пробрасывают просьбу ещё на
  уровень вниз — на случай вложенного плеера. Все отложенные шаги проверяют,
  что фокус всё ещё "наш" (body или сам плеер), чтобы не выдёргивать его, если
  пользователь ушёл в комментарии или в поиск.
- **Плеер отвечает на каждую просьбу, а не только при удаче** (`focused`,
  `host`, `hasVideo`, `nested`). Это не украшение, а единственный способ
  отлаживать эту ветку: из топ-документа в чужой origin не заглянуть, и без
  ответа "скрипт меня не слышит" неотличимо от "слышит, но `<video>` у него
  уровнем ниже".
- **`focused: true` засчитывается за конкретный кадр, пинги не обрываются**
  (1.4). Старый, ещё не снесённый кадр подтверждает фокус сразу (~30 мс), а
  Alloha пересоздаёт iframe через ~2 с после клика и ещё раз через ~3 с —
  удалённый `<iframe>` уносит фокус на body, и Space листает страницу (так
  было до 1.4, когда пинги останавливались по первому `true`, а запасной
  `focusPlayer` стоял на 1200 мс). Теперь топ помнит `focusedFrame` — кадр,
  от которого пришло `true` (проверка `fromPlayer`), и все 10 с окна на каждом
  тике сверяет: если текущий `#video iframe` уже другой — снова фокусит его и
  просит `<video>`. Проверено замером на живой странице.
- **`kodikplayer.com` вкладывает в себя ещё один iframe** (`ls.kodikres.com`),
  поэтому этот домен тоже стоит в `@match`. У вложенного фрейма referrer —
  уже домен плеера, а не сайта, так что referrer-гейт его не пропустил бы;
  хоткей там включается по факту получения нашей же просьбы сверху
  (`installKeyBridge` из моста фокуса) — иначе после перевода фокуса на
  `<video>` во вложенном фрейме перестал бы работать сам `Ctrl+←/→`.
- **Псевдо-fullscreen (1.3) растягивает сам `#video iframe` вставленным
  `<style>`**, а не контейнер: сайт на каждую серию пересоздаёт iframe вместе с
  его родителем-`div`, так что стили по селектору — единственное, что
  переживает `Ctrl+←/→` без переустановки. Предки `.wKBD` (z-index 2) и
  `.content-block` (z-index 1) — свои stacking context'ы, без правки шапка
  сайта и список серий рисуются поверх плеера; поэтому предкам с z-index на
  время режима ставится атрибут-маркер с максимальным z-index (переразметка
  по `MutationObserver` на `#video` — у другой озвучки `.wKBD` свой).
  F9/Esc внутри плеера идут наверх `FS_MESSAGE` через мост хоткея, топ
  принимает их только из своего плеера, включая вложенные фреймы.
- **Alloha (`alloha.yani.tv`) — плеер AllPlay, форк Plyr** (классы
  `allplay__*`, кнопки `button[data-allplay=...]`). Кнопка PiP —
  `button[data-allplay="pip"]`, обработчик висит прямо на ней, поэтому
  `click` в capture на `window` + `stopImmediatePropagation` срабатывает
  раньше: `requestPictureInPicture` не вызывается вовсе (проверено шпионом на
  прототипе), PiP-окно не мигает, вместо него — псевдо-fullscreen.
  Отлаживать Alloha отдельно неудобно: без встраивания во фрейм сервер отдаёт
  заглушку «контент недоступен» (referrer не помогает). Рабочий приём —
  открыть адрес плеера во вкладке, а там встроить его же `<iframe>` в
  страницу (тот же origin → `contentDocument` доступен).
  - **Чистка субтитров от остатков ASS (1.8)** — тот же
    `installAssCueCleaner`, что в `ajsubs-episode-nav` 1.9 (описание там),
    ставится вместе с мостом хоткея. На 2026-11 AllPlay здесь прямо на
    `alloha.yani.tv`, без вложенного фрейма. Проверено на «Монологе
    фармацевта 3» (дорожки Crunchyroll: «Надписи», «Полные», English): мусора
    в них нет, чистильщик срабатывает на `load` всех трёх и ничего не меняет
    (число реплик = числу в файле). Реальный мусор проверен только на animejoy.
  - **Размер субтитров Shift+↑/↓ (1.9)** — тот же `installCaptionSizeKeys`,
    что в `ajsubs-episode-nav` 1.10 (описание там). Здесь проверен только
    синтаксис.
  - **Дубли-слои ASS-надписей (1.10, слияние перекрывающихся — 1.12) и
    кнопка-метла вкл/выкл чистки (1.11)** — тот же код, что в
    `ajsubs-episode-nav` 1.11–1.13 (описание там). Здесь
    проверен только синтаксис.
- **Плеер CVH — матрёшка с shadow DOM** (1.5). `ru.yummyani.me/iframeCVH.html`
  — только обёртка: в ней `<video-player>` с открытым `shadowRoot`, в нём
  `iframe.vk-player-iframe` на `player.cdnvideohub.com` (тоже рисует всё в
  shadow root). Домен cdnvideohub в `@match`; его referrer — `ru.yummyani.me`,
  так что referrer-гейт проходит сам. Поиск `<video>`/`<iframe>` в мосте
  фокуса — `deepQueryAll` с заходом в открытые shadow root, активный элемент —
  `deepActiveElement`, а просьба фокуса шлётся и в `contentWindow` найденных
  так iframe (iframe из shadow DOM в `window.frames` мог не попасть). Уровень
  без своего `<video>` фокусит вложенный `<iframe>`. Мост хоткея с 1.5 на
  `window` в capture со `stopImmediatePropagation`, цель — `composedPath()[0]`.
- **CVH: серию после `Ctrl+←/→` запускаем вручную** (автозапуск был в 1.6,
  убран в 1.7 — работал некорректно). Внутри CVH плеер VK Video, его
  keydown-обработчик висит на корне плеера и пропускает клавиши только в
  состоянии «играет»/«пауза»: пока новую серию не запустили, стрелки и Space
  он игнорирует, и прокрутка всплывает из iframe на страницу. Фокус при этом
  стоит правильно (`focused: true` от cdnvideohub). Если автозапуск
  понадобится снова: обёртка CVH принимает от родителя
  `postMessage({method: 'play' | 'pause' | 'seek' | 'volume'})` и шлёт наверх
  `{key: 'player_video_started' | 'player_play' | ...}` — см. коммит 1.6.
- **Отладка в автоматизированной вкладке: окно должно быть видимым.** Обёртка
  CVH ждёт 50 кадров `requestAnimationFrame`, прежде чем убрать заглушку, а в
  скрытой вкладке (`visibilityState: hidden`) rAF не тикает — плеер навсегда
  висит на логотипе. Отдельно `iframeCVH.html` не открыть: без фрейма
  редиректит на YouTube.
- `ru.yummyani.me` **как самостоятельный сайт не поддержан**: это другой,
  переписанный фронтенд (Vite/react-select, никакого `#video`), где активная
  серия помечается не фоном, а отдельной цветной полоской — по вычисленным
  стилям пункты там неотличимы друг от друга. Для него нужен отдельный
  профиль; домен в `@match` стоит только ради iframe-ветки.

### `kinogo-allplay-episode-nav.user.js`
Сайт: `kinogo.ec`, "Плеер 3" (AllPlay, iframe с `*.stravers.live`) и
"Смотреть онлайн" (Playerjs, iframe с `cinemar.cc`).
- `Ctrl+←/→` — жмёт кнопки серий плеера: у AllPlay
  `button[data-allplay="next"|"prev"]`, у Playerjs
  `.playlist-nav > button.playlist-next|playlist-prev` (у крайней серии —
  `disabled`). Нажатие внутри фрейма глушится `stopImmediatePropagation` на
  `window` в capture — голые стрелки у плееров это перемотка, и Ctrl они не
  проверяют.
- "Плеер 1" (`api.ortified.ws`, player-venom) **не поддержан**: в
  автоматизированной вкладке его UI так и не отрисовался. По исходникам
  `player-venom@0.3.6` при `ui.prevNext` у него есть кнопки
  `.episode-next`/`.episode-prev` (класс не хэширован) — если понадобится,
  начинать с этого.
  Из топ-документа они недостижимы (cross-origin), поэтому топ шлёт
  `postMessage` в iframe, а жмёт ветка скрипта внутри плеера. Собственный
  хоткей внутри плеера включается только при `document.referrer` = kinogo
  (stravers.live встраивают и другие сайты).
- **Чистка субтитров AllPlay от остатков ASS (1.4)** — тот же
  `installAssCueCleaner`, что в `ajsubs-episode-nav` 1.9 (описание там),
  включается вместе с хоткеем (referrer = kinogo). Домен Плеера 3
  (`*.stravers.live`) совпадает с Alloha на animejoy; на kinogo вживую не
  проверялось — только синтаксис.
- **Размер субтитров AllPlay Shift+↑/↓ (1.5)** — тот же
  `installCaptionSizeKeys`, что в `ajsubs-episode-nav` 1.10 (описание там),
  включается вместе с хоткеем; с kinogo.ec нажатие пробрасывается в
  `iframe.lazy`. На kinogo — только синтаксис.
- **Дубли-слои ASS-надписей (1.6, слияние перекрывающихся — 1.8) и
  кнопка-метла вкл/выкл чистки (1.7)** — тот же код, что в
  `ajsubs-episode-nav` 1.11–1.13 (описание там). На kinogo
  — только синтаксис.
- `F9` — псевдо-fullscreen, `Esc` — выход (как на rezka.ag, но без перехвата
  PiP). Растягивается `position: fixed` не `<video>` (он в чужом origin), а
  контейнер iframe `.kg-video-container`: iframe в нём `absolute` с inset 0 и
  тянется сам. Нажатия внутри плеера пробрасываются наверх `postMessage`-ом,
  топ принимает их только с `e.source === iframe.contentWindow`.
- Все вкладки ("Смотреть онлайн" / "Плеер 1" / "Плеер 3") — **один и тот же**
  `iframe.lazy`, сайт меняет ему только `src`. Поэтому `iframe.lazy` верен для
  любой вкладки, а псевдо-fullscreen переживает смену плеера и серии.
- Версия `1.1` занята откаченным коммитом (автоклик "Продолжить просмотр"),
  следующая после `1.0` — сразу `1.2`: Tampermonkey мог успеть подтянуть
  `1.1` и не увидел бы апдейт с тем же номером.

### `ajsubs-episode-nav.user.js`
Сайты: `ajsubs.ru`, `animejoy.ru` и его зеркало `otakujoy.fun` (AnimeJoy). `Ctrl+←/→` — переключение серии текущей
озвучки/плеера (у Alloha — кнопками самого плеера, с 1.7; у Alloha же чистит субтитры от ASS-мусора, с 1.9, и меняет их размер по Shift+↑/↓, с 1.10; дубли-слои надписей, с 1.11, слияние перекрывающихся — с 1.13; кнопка-метла вкл/выкл чистки, с 1.12), фокус после переключения — на `<video>` внутри плеера. `F9` —
псевдо-fullscreen любого плеера (`Esc` — выход), с 1.4. Мост
фокуса и хоткея из iframe — та же схема, что в `yummyani-episode-nav`
(`postMessage` наверх, referrer-гейт по `ajsubs.ru`/`animejoy.ru`/`otakujoy.fun`, просьба
сфокусировать `<video>` серией пингов до подтверждения).

- **Страницу тайтла на otakujoy/animejoy перестраивает `animejoy-title-ui`**
  (см. ниже): плейлист `.playlists-ajax` он переносит в свой интерфейс целиком,

### `aliexpress-zestawienie-generator.user.js`

написать заново на основе актуального zestawienie, чем поднимать из истории

  "Zestawienie (PDF)".
- Редактор открывается модалкой поверх текущей страницы (все id/классы с
  префиксом `zg-`, чтобы не конфликтовать с версткой AliExpress).
- Реквизиты покупателя (своей фирмы) хранятся через `GM_setValue`/
  `GM_getValue`, редактируются через пункт меню Tampermonkey
  ("⚙️ Ustawienia nabywcy").
- PDF собирается через `pdfmake` — подключён через `@require` с cdnjs,
  версия закреплена (`0.3.3`); `vfs_fonts.js` от той же версии подключён
  отдельным `@require` следом (порядок важен — `vfs_fonts.js` регистрирует
  шрифты в уже загруженном `pdfMake`).
- Оригинальные CSS-селекторы парсинга DOM AliExpress — при изменении
  вёрстки AliExpress могут потребовать правки (это уязвимое место любого
  DOM-скрапинга, не специфика userscript'а).
- Документ называется "ZESTAWIENIE WŁASNE", не "FAKTURA"; в PDF есть явная
  строка-дисклеймер, что это не faktura sprzedawcy.
- Нет лого AliExpress в PDF.
- Нет разбивки Netto/VAT/Brutto и нет отдельного номера документа (`FV-...`) —
  только "RAZEM (zapłacono)", дата и номер zamówienia (сам заказ, не выдуманный
  номер документа).
- **Итоговая сумма и строки под ней — дословный дубликат блока "Rozbicie ceny
  zamówienia" со страницы заказа, а не вычисленная разница.** Раньше
  `openGenerator` считал `totalOrderPrice - itemsSum` и подписывал остаток
  одной строкой "Koszt dostawy (Shipping)"/"Rabat / Kupon (Discount)" — это
  было неверно уже потому, что в остаток попадали сразу все компоненты
  (Kupon sklepu, Kupon AliExpress, Monety, Szacowane opłaty importowe), не
  различимые между собой, а "W dostawie: Bezpłatna dostawa" вообще не деньги.
  Теперь `scrapeData()` сначала зовёт `expandPriceBreakdown()` (клик по
  `.switch-icon` — блок рендерится в DOM только после разворачивания, ждём
  ~500мс), затем `scrapePriceBreakdown()` читает ВСЕ строки
  `.order-price-item` (`data-pl="order_price_item_title"`/`"...value"` —
  общий компонент-строка для всего блока) без фильтрации — это автоматически
  даёт Podsuma (она тоже такая строка, просто всегда видна) и всё, что
  появляется после разворачивания (W dostawie, Kupon sklepu, Kupon
  AliExpress, Monety, Szacowane opłaty importowe), в том порядке, в каком их
  показывает AliExpress. Строки хранятся как `{title, value}` — сырой текст
  без парсинга чисел (включая "Bezpłatna dostawa" как есть) — и просто
  выводятся построчно и в модалке (`#zg-breakdownRows`), и в PDF, над
  финальной "RAZEM (zapłacono)". Финальная сумма при этом по-прежнему берётся
  из `.rightPriceClass` (`data.totals.totalGross`, выставляется один раз в
  `openGenerator` и не пересчитывается при редактировании таблицы товаров —
  таблица товаров теперь чисто информационная детализация закупки, а не
  единственный источник итога).
- **`expandPriceBreakdown()` не кликает по `.switch-icon` вслепую.** Клик по
  стрелке — это toggle, а модалка генератора не перезагружает страницу, поэтому
  раньше второй запуск генератора на той же странице сворачивал блок обратно (в
  модалке оставались только Podsuma и Suma), третий снова разворачивал. Состояние
  самой иконки в DOM AliExpress ненадёжно (класс/атрибут не меняются предсказуемо),
  поэтому проверяется эффект: считаем видимые `.order-price-item` до и после клика
  и, если их стало меньше, кликаем ещё раз (значит блок был уже развёрнут и мы его
  свернули).
- Блок Sprzedawca/Nabywca — один последовательный текстовый блок, а не два
  зеркальных столбца.
- Кнопка "Pobierz PDF + Paragon" в редакторе скачивает **два файла одним
  кликом**: сам zestawienie и оригинальный paragon, который рендерит сам
  AliExpress в своей модалке "Paragon" (`capturePLReceiptPng`). Эта модалка —
  отдельный iframe того же originu (`iframe.invoice-iframe-container`);
  скачивание внутри неё — чистый client-side canvas, `<a download>` с
  `href="data:image/png;...”`, без единого сетевого запроса. Скрипт сам жмёт
  их кнопку "Paragon" → дожидается iframe → подменяет
  `contentWindow.HTMLAnchorElement.prototype.click`, чтобы поймать эту же
  data-URI в момент их собственного клика по `#download-receipt` внутри
  iframe → скачивает копию как `Paragon_{orderId}.png`, ничего в ней не
  меняя (это файл, сгенерированный самим AliExpress, не наша реконструкция).
  Пара с zestawieniem сознательно остаётся **двумя файлами**, не мержится в
  один PDF — так происхождение каждого однозначно по самому факту раздельных
  файлов, а не по тексту дисклеймера внутри одного документа; wFirma и так
  штатно допускает несколько вложений на один wydatek. Если селекторы
  AliExpress (`.order-status.order-block`, текст "Paragon",
  `iframe.invoice-iframe-container`, `#download-receipt`) изменятся —
  `capturePLReceiptPng` просто вернёт `null` и zestawienie всё равно
  скачается (деградация не блокирует основной сценарий).
- Два программных скачивания за один клик — это то, на чём Chrome по
  умолчанию блокирует второе ("automatic downloads" permission per-site,
  видно как маленькая иконка в адресной строке). Поэтому `generatePdf(data)`
  вызывается **первым**, сразу, до всех await'ов из `capturePLReceiptPng` —
  если Chrome что-то заблокирует, это будет paragon (второй, менее
  критичный), а не сам zestawienie.

Назначение — вспомогательный документ к оригинальному paragon/potwierdzenie
zamówienia + dowodowi zapłaty для KPiR/wFirma (там это заводится как "Inny
dowód księgowy", а не "Faktura"), а не самостоятельная замена faktury.

  «Finished») и год, если слайдер больше `min` (1950 = «любой»,
  `entryFilters.year` тогда 1950 и список полный). Фильтры живут в
  `MediaList.entryFilters` (`format`, `status`, `year`, `genres`,
  `country`). Проверено (код вставлен): иконка открывает/закрывает строку;
  Format TV → «1», + год 2015 → «2» (11 карточек), сброс → пусто, 108;
  состояние из `localStorage` применяется. Несколько `$emit` подряд в одном
  тике сайт может не применить — в тесте сбрасывать по одному.
- **Вид списка запоминается аккаунтом**, а не только
  `localStorage['anime-list-layout']`: после проверки вида строками (клик
  обратно на карточки промахнулся) у пользователя открывались строки при
  `localStorage` = `cards`. После тестов переключателя вида — вернуть
  карточки (`.layout-switch` → 3-й `span`, `th-large`).
- Кнопки вида (`.lists > .actions`, `position: absolute`) остаются над
  первым списком справа.
- Проверено вставкой CSS в начало `<head>` (как ставит Tampermonkey):
  выпадашка Format открывается под полем, выбор «TV» фильтрует, вкладка
  Watching переключает (URL `/animelist/Watching`), вид строками тоже на
  всю ширину; горизонтальной прокрутки нет. Окно 1320px (контейнер
  1140px); у пользователя 1620px (контейнер 1520px) — не проверено, манга
  и чужой список — тоже.
- Проверено вставкой CSS на `/user/khanermi/animelist` (108 карточек, Dark

## Общие детали по будущим задачам

- Новый скрипт — новый файл в корне, с обязательными
  `@updateURL`/`@downloadURL` по образцу существующих (иначе автообновление
  не заработает).
- CSS из скрипта с `document-start` стоит в `<head>` **раньше** стилей
  сайта: при равной специфичности побеждает сайт. Поднимать специфичность
  (`html body …`) и проверять стиль на том месте, куда его ставит
  Tampermonkey, а не дописанным в конец (`anilist-list-cards` 1.0). Если у
  сайта scoped-стили Vue (`[data-v-…]` — атрибут весит как класс), `html
  body` мало — префикс `html:not(#tm)` даёт вес id (`anilist-list-filters`).
- Если скрипту нужна внешняя библиотека — тянуть через `@require` с
  зафиксированной версией на CDN (cdnjs/jsdelivr), не копировать код
  библиотеки в репозиторий.
- Изменения в существующем скрипте всегда сопровождаются бампом `@version`
  в этом же коммите.
- Никакого README/CI/package.json не заводим — репозиторий сознательно
  остаётся плоским набором `.user.js`.
- Процесс доработки плееров (этапы, отладка чужих iframe, тесты, релиз) —
  скилл `.claude/skills/browser-tunes/SKILL.md`. Он же подключён симлинком в
  `~/.claude/skills/browser-tunes`, потому что сессии обычно стартуют не из
  папки репо. Новый общий урок — туда, факт про конкретный сайт — сюда.
